# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Supabase base grants — A freshly provisioned Supabase project may have NO base privileges (USAGE + ALL) on public tables for anon/authenticated/service_role, so every query fails with `permission denied for table X` even with correct RLS. This was the root cause of the session's org-creation blocker. Mitigated by `supabase/migrations/00016_restore_public_grants.sql`. → Before diagnosing any RLS/permission error, verify grants exist on the target project; do not assume the standard grant set was applied.
- [ ] CONSTRAINT: RLS role claims — `authorize()` and RLS policies read JWT `app_metadata` claims that are only set by a service-role admin client + session refresh (no `custom_access_token_hook` is registered in this project). Claims updates via the anon-key client silently do nothing. → Any auth/role state change must go through the service-role client and the session must be refreshed before RLS reads fresh claims.
- [ ] CONSTRAINT: Next.js in this repo is NOT the Next.js from training — `node_modules/next/dist/docs/` contains the authoritative guides (AGENTS.md block). Breaking changes exist (e.g. `middleware` is deprecated in favor of `proxy`; `localePrefix: 'always'` rewrites unprefixed routes). Read the relevant guide before writing Next.js code.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Missing base-grant assumption | Diagnosing RLS/permission failures without first checking anon/authenticated/service_role privileges on the target project | blocking | `00016_restore_public_grants.sql` restores them; verify grants (or their absence) before touching RLS policies |
| anon-key claim writes | Setting JWT claims with the anon-key client so RLS never sees the role | blocking | Use the service-role admin client to update `app_metadata`, then refresh the session (see `src/app/[locale]/onboarding/actions.ts`) |
| i18n middleware order | Running `handleI18nRouting` before the public-path short-circuit rewrote `/login` → `/en/login` (404) | blocking | Public auth/landing paths bypass i18n routing first (`src/middleware.ts`) |
| Nested document elements | `[locale]/layout.tsx` rendering its own `<html>/<body>` inside the root layout broke hydration + RSC navigation | blocking | Root layout is the single owner of document elements; locale layouts render fragments only |
| Effect-as-state-init | `useState(() => loadRole())` ran async state updates that could fire after unmount | advisory | Use `useEffect` + cancellation flag (see `BottomNav.tsx`) |
| SPLIT of enum ADD VALUE + consumers | `ADD VALUE` and its consumers must never share one migration file (55P04 seed split lesson from 02-08) | advisory | Separate enum value additions from consumer migrations |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
