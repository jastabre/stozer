# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Floating-point currency — Must use integer cents/para from schema design. Changing later means migrating every financial record. All balance math in SQL, format only at UI layer.
- [ ] CONSTRAINT: RLS on every table — One forgotten `ENABLE ROW LEVEL SECURITY` means data leakage. CI gate this. Test with two seeded organizations.
- [ ] CONSTRAINT: Feature bloat — STOZER-BRIEF.md is the law. Every "just one more" feature delays the clubs that need the basics today. Do not add features not in the locked V1 scope.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Tenant data leakage | Missing RLS on a table exposes all club data | blocking | Enable RLS on every table at creation, CI check for un-RLS'd tables, test with two seeded organizations |
| FIFO race condition | Concurrent payments can double-allocate the same charge | blocking | PL/pgSQL function with FOR UPDATE SKIP LOCKED, atomic transactions, idempotency keys on imports |
| Floating-point money | JavaScript 0.1 + 0.2 bugs in financial calculations | blocking | Store all amounts as integer cents/para, format only at UI layer, all balance math in SQL |
| Feature scope creep | Building features not in STOZER-BRIEF.md or locked V1 scope | advisory | Brief is law, maintain "not now" list, ship MVP to beta clubs |
| ORM over Supabase | Prisma/Drizzle adds abstraction over native Postgres access, complicates RLS | advisory | Use Supabase JS client directly, no ORM |
| Auth layer mismatch | Clerk/NextAuth breaks native RLS integration via auth.uid() | advisory | Use Supabase Auth exclusively |
| RLS performance | Policies with subqueries become sequential scans at 10k+ rows | advisory | Simple column comparisons in RLS, (SELECT ...) wrapper, index organization_id as first column |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
